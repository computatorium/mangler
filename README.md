# mangler

A JavaScript / CSS / HTML **obfuscator, minifier, and bytecode virtualizer**, written in Rust.

`mangler` rewrites source into compact or deliberately unreadable
output. It minifies, renames, encodes strings, flattens control flow, injects
decoys, and — for JavaScript — can lift functions or an *entire program* into a
custom register-based **bytecode VM** so the logic survives as interpreted bytes
rather than readable source.

Virtualization is **bail-to-safe**: unsupported constructs remain native, and
coverage can be required explicitly for selected functions. Output is
**deterministic** under a fixed `--seed`
(same input + seed ⇒ byte-identical result).

---

## Build

```sh
cargo build --release
# binary at target/release/mangler
```

Requires a recent stable Rust toolchain. The workspace is pure Rust; the test
suite executes generated JS through an in-process engine. Production-runtime
checks additionally exercise Node and Chrome when installed.

## Quick start

```sh
# JS from stdin → stdout
cat app.js | mangler - --lang js --preset high

# Mangle every JS/CSS file under src/ into dist/ with a fixed seed
mkdir -p dist
mangler src/ -o dist/ --preset max --seed 42

# Mangle all CSS in place (overwrite sources)
mangler "assets/**/*.css" --in-place
```

Inputs are files, directories (recursed), quoted glob patterns, or `-` for stdin.
For multiple inputs, use `--in-place` or an existing output directory. Inputs are
deduplicated, and ambiguous output destinations are rejected before writing.
Existing literal filenames take precedence over glob syntax, including names
such as `[id].js`. Directory traversal excludes a nested output directory, so a
repeat build does not transform its previous output.

The driver loads at most one source per worker and limits each batch to roughly
16 MiB of source text; a larger individual file runs alone. Outputs are replaced
atomically, preserving existing file permissions. `--keep-going` applies to
discovery, read, transform, and write failures; destination collisions always
stop the build before outputs are written.

## Presets

`--preset` (default `high`) sets a baseline every individual flag can override:

| Preset    | What you get |
|-----------|--------------|
| `minify`  | Whitespace/identifier minification only — no obfuscation. |
| `low`     | Minify + local mangling + `encode` strings. |
| `medium`  | Adds safe global indirection. |
| `high`    | Adds control-flow flattening, `encrypt` strings, hex identifier names, self-defending + debug-protection guards. |
| `max`     | Strongest obfuscation defaults; function/program virtualization remains opt-in. |

## Driver flags

| Flag | Purpose |
|------|---------|
| `-o, --output <PATH>` | Output file, or directory for multiple inputs. |
| `--in-place` | Overwrite each input with its output (conflicts with `-o`). |
| `--config <TOML>` | Load defaults from a TOML file (explicit flags win). |
| `-j, --jobs <N>` | Worker threads (default: CPU count; `1` = serial). |
| `-v, --verbose` | Print notes + a per-file size report to stderr. |
| `--keep-going` | Skip failed inputs instead of aborting (exit code still reflects failures). |
| `-l, --lang <js\|css\|html>` | Force input language (required for stdin). |
| `--seed <U64>` | Fixed RNG seed for reproducible output. |
| `--verify` | Re-parse the final protected output; does not change generated bytes. |

Exit codes: `0` all inputs ok; `1` one or more failed (parse, I/O, or `--verify`).

## Obfuscation passes

Each is a per-pass override of the preset default; absence = preset default.

| Flag | Values | Notes |
|------|--------|-------|
| `--mangle` | `true\|false` | Local-identifier mangling. |
| `--identifier-naming` | `short\|hex\|soup` | `short` = `a,b,…`; `hex` = `_0x4e2a`; `soup` = homoglyph names. |
| `--strings` | `none\|encode\|encrypt` | String literal obfuscation. |
| `--control-flow` | `true\|false` | Control-flow flattening. |
| `--dead-code` | `0.0`–`1.0` | Decoy-code injection ratio (`0.0` disables). |
| `--global-indirect` | `off\|safe\|aggressive` | Indirect free-global references. |
| `--self-defending` | `true\|false` | Check embedded probe and unambiguous top-level function source. |
| `--debug-protection` | `true\|false` | Debugger trap. |
| `--harden-global-anchor` | flag | Legacy option; lexical accessor tables need no global-object anchor. |
| `--keep-names <GLOBS>` | csv globs | Identifier names to preserve from renaming. |

### String-decode key binding

Bind string decoding to a runtime value so the output only decodes in the
intended environment:

| Flag | Purpose |
|------|---------|
| `--domain-lock <HOST>` | Decode only on the given hostname (sugar for the two flags below). |
| `--key-source <EXPR>` / `--key-expected <VAL>` | Decode keyed off an arbitrary runtime JS expression. |
| `--remote-key [<EXPR>]` | Key off a session/remote slot (defaults to `globalThis.__MANGLER_SESSION_KEY`). |
| `--strings-in-vm <bool>` | Route the string decoder through the bytecode VM. |
| `--self-coupled-key <bool>` | Couple the key to the decoder bytes (fragile: re-minification breaks decoding). |
| `--exec-trace-key <bool>` | Oblivious execution-trace key (robust to re-minification). |

## Virtualization (JavaScript)

`mangler` can compile JS to a diversified, register-based bytecode VM that is
spliced back into the module: the original logic becomes a constant table plus a
generated interpreter, and call sites become thunks that re-enter the interpreter.
Each output file draws its own VM diversity from the seed.

Virtualization increases the effort needed to inspect or modify delivered code;
it is not a security boundary. A person controlling the browser can inspect
runtime values and change client behavior. For payment applications, keep secret
keys, authoritative prices, payment authorization, and transaction validation on
the server. Use mangler to protect the implementation of client logic, alongside
those server checks.

Minification and virtualization serve different goals. Start with `--preset
minify` when download size matters, then virtualize selected sensitive functions.
The generated interpreter adds bytes and runtime overhead; enabling every
obfuscation pass is not a size optimization.

### Named-function mode

```sh
mangler app.js --virtualize 'hot*'
```

Virtualizes every function whose (inferred) name matches the glob. Names are
inferred from the function's own identifier, its binding (`const render = …`,
`obj.render = …`), or its object/class property key. Strict and sloppy bodies route
to separate interpreter variants to preserve `this` and assignment semantics.

To make protection coverage a build requirement:

```sh
mangler app.js --preset minify --require-virtualized 'payment*' -v -o app.protected.js
```

`--require-virtualized <GLOB>` selects matching functions when no explicit
`--virtualize` target is given. The build fails if no function matches or any
matching function remains native, including excluded or unsupported functions.
Verbose notes explain which selected functions virtualized and why a target was
kept native. Use this gate for code whose protection must survive source changes.
The required-coverage gate accepts JavaScript inputs; CSS and HTML inputs are
rejected because they cannot satisfy its function-level contract.

### Whole-program mode

```sh
mangler app.js --virtualize-program
```

Wraps the entire top level and recurses into every reachable function. The
program is **partitioned** at `import`/`export`/top-level-`await` boundaries;
each maximal run of wrappable statements becomes its own chunk, and a run that
fails to compile is adaptively bisected so a single unsupported statement stays
native while its neighbors still virtualize. Cross-run `var`/`function` data flow
is preserved automatically.

### Keeping hot paths native

A bytecode VM is far slower than native JS, so a 60 fps render loop should stay
native. Exclude it by name:

```sh
mangler app.js --virtualize-program --virtualize-exclude 'render*'
```

Excluded (and structurally ineligible — `async`, generators, etc.) functions run
as **native JS at full speed inside the VM frame** via a native-closure escape
hatch, while still capturing the surrounding virtualized locals. With `-v`,
`mangler` prints a note listing which functions were kept native so you can
confirm your hot path. Note: exclusion is **name-based and manual** — a bare
anonymous callback (`requestAnimationFrame(() => …)`) has no name to match; give
it a name and exclude that.

### Class and regular-expression compatibility options

Class syntax carries runtime behavior that function/prototype emulation cannot
reliably preserve. Mangler keeps the native class skeleton and can protect
eligible method bodies. Constructors, fields, inheritance, and private state
retain their native JavaScript semantics; coverage notes distinguish protected
methods from code left native.

| Flag | Effect |
|------|--------|
| `--virtualize-desugar-class` | Protect eligible class method bodies while retaining native class syntax. |
| `--virtualize-desugar-regex` | Legacy compatibility option; regex literals retain their intrinsic semantics. |

Both are whole-program options. A regex literal is not rewritten through the
mutable `RegExp` binding.

## Configuration file

Transform flags are also settable from a `--config` TOML file (explicit CLI
values override it); unknown keys are a hard error. Input/output paths, worker
count, verbosity, and `--keep-going` are driver options supplied on the CLI.

```toml
preset = "max"
seed = 7
strings = "encrypt"
identifier_naming = "soup"
keep_names = ["myExport", "init*"]
harden_global_anchor = true
```

## Workspace layout

| Crate | Role |
|-------|------|
| `mangler-cli` | Binary driver (`mangler`): argv, I/O, parallelism. |
| `mangler-config` | The single flag declaration (clap + serde) + validation. |
| `mangler-core` | Shared types: errors, notes, RNG, pass traits. |
| `mangler-passgraph` | Dependency-ordered pass scheduler. |
| `mangler-jsast` | JS AST analysis helpers (eligibility, binding names). |
| `mangler-js` | JS passes: mangle, strings, control-flow, virtualize, … |
| `mangler-vm` | The bytecode VM: compiler, ISA, interpreter codegen, serializer. |
| `mangler-css` / `mangler-html` | CSS and HTML minification/mangling. |
| `mangler-testkit` | Differential fuzzing + in-process eval harness. |

## Determinism & safety

- **Deterministic:** same input + `--seed` ⇒ byte-identical output, including VM
  diversity and partition boundaries.
- **Bail-to-safe:** any construct that cannot be lowered soundly is left native.
  Differential equivalence (original vs. output: identical stdout, thrown errors,
  and side-effect order) is the test gate for every pass.

`--verify` checks syntax of the actual final artifact. It does not prove runtime
equivalence or protection coverage. Test generated code in your target host,
including module loading, asynchronous behavior, and the application paths you
choose to virtualize.

The self-defending guard checks its embedded probe and unambiguous top-level
function declarations, throwing on detected changes. It does not authenticate
arbitrary top-level statements or prevent replacement of the guard. Domain and
remote-key binding condition string decoding on runtime values, observable to someone
controlling that runtime. Debug protection intentionally interferes with active
debugging. Self-coupled keys depend on exact decoder bytes, so do not reformat or
minify the generated output afterward.

## Development checks

```sh
cargo test --workspace --locked -- --test-threads=2
cargo clippy --workspace --all-targets --locked -- -D warnings
```

To require actual Node and Chrome execution, supply absolute engine paths:

```sh
MANGLER_TESTKIT_NODE=/absolute/path/to/node \
MANGLER_TESTKIT_CHROME=/absolute/path/to/chrome \
MANGLER_TESTKIT_REQUIRE_ENGINES=1 \
cargo test --workspace --locked -- --test-threads=2
```

The differential harness records typed values, exceptions, logs, and asynchronous
outcomes under execution, memory, and job limits. A timeout or unsupported
observation fails equivalence; two incomplete runs never count as a pass.

Generated size and Node startup/runtime measurements are reproducible with:

```sh
cargo build --release --locked
/absolute/path/to/node scripts/measure-vm.cjs --binary target/release/mangler --check
```

The benchmark checks byte budgets and behavioral equivalence. Timings are
reported separately because they depend on the machine and JavaScript engine.
See [recorded VM measurements](docs/VM_BENCHMARK.md) for size reductions and the
runtime cost of preserving live captures and lexical bindings.
